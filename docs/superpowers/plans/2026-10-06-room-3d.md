# Automatic room 3D implementation plan

> Use superpowers:subagent-driven-development for isolated implementation and review tasks.

**Goal:** Automatically reconstruct uploaded room photographs and publish the ready scene in the property description.

**Architecture:** PostgreSQL stores one versioned job per property. An authenticated GPU worker claims jobs with leases, downloads versioned photographs, trains Nerfstudio Splatfacto, and uploads a validated PLY plus camera metadata. Express serves current models using existing property visibility rules. Browser viewing is loaded on demand.

**Tech stack:** Express, PostgreSQL, Python standard library worker, Nerfstudio/COLMAP, GaussianSplats3D browser bundle.

## Global constraints

- Maximum 200 photographs per property; maximum 10 per upload request; existing 8 MB image limit.
- Minimum 20 photos by default, configurable; debounce 60 seconds.
- Draft and archived models are accessible only to the owner. Public models require published status.
- Job revisions and lease tokens must reject stale downloads, completion, and failure callbacks.
- No credentials in public DTOs, URLs, logs or Git. No shell interpretation of user data.
- No reconstruction success claimed without a real GPU run. Missing worker is clearly reported.
