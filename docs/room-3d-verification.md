# Автоматический 3D-просмотр помещений

6 октября 2026 года.

## Что реализовано

Загрузка фотографий транзакционно обновляет версию модели и задание в PostgreSQL. Обработка запускается без отдельной кнопки, после паузы 60 секунд и при наличии минимум 20 фото (оба значения настраиваются). Лимит объекта увеличен до 200 фото; браузер отправляет партии по 10 и сохраняет успешно загруженные партии при последующем сбое. Удаление фото и изменение категории отменяют старую версию. Очередь, ограниченные повторы и аренды заданий сохраняются между перезапусками.

Готовая модель отображается рядом с описанием объекта в локальном просмотрщике Gaussian Splatting. Она доступна всем посетителям опубликованного объекта. Черновики и архив доступны только владельцу. Загрузка просмотрщика происходит по нажатию; поддерживаются мышь, касания, клавиатура, сброс ракурса и полный экран. Если обработчик не настроен, владелец видит сообщение о недоступной обработке, а посетители продолжают видеть фотографии и описание.

GPU-обработчик выполняет COLMAP, Splatfacto и экспорт PLY. Загруженные сервером WebP конвертируются в RGB PNG, поддерживаемый выбранной версией Nerfstudio. API использует отдельный секрет; версия и аренда задания проверяются при чтении фото и перед сохранением результата. Сервер проверяет бинарный PLY, размер, конечность чисел и начальный ракурс. Подробности запуска: [room-3d-setup.md](room-3d-setup.md).

## Ограничение запуска

Пользователь сообщил, что GPU-сервера нет. Секрет `ROOM_MODEL_WORKER_TOKEN` на рабочем сайте не включаем без доступного обработчика. Реальная реконструкция помещения на GPU и сборка контейнера GPU-обработчика пока не подтверждены. Синтетическая сцена проверяет только просмотрщик и интеграцию, а не качество реконструкции. Для включения генерации нужны GPU-хост, настройка обработчика и проверка на последовательной серии снимков реального помещения.

Обновление Dockhost должно включать код сайта и миграцию; оно само по себе не предоставляет вычислительный GPU-сервис.

## Публикация Dockhost

Коммит приложения `e268403` отправлен в `main` по SSH. После задержки пересборки на https://477a-oc71-643k.gw-1a.dockhost.net/ подтверждены ответы 200 для `/api/health`, нового `/api/properties/2/model`, `/js/room-model.js`, `/js/forms.js`, локального бандла просмотрщика и страницы `/property/2`. Новый API возвращает `model.state=none` для публичного объекта без модели. Заголовок страницы объекта содержит необходимую политику WebAssembly.

В живом Chromium на ширине 1440 и 390 пикселей проверены описание объекта, загрузка фотографии, запрос нового API, скрытие отсутствующей модели, отсутствие преждевременной загрузки бандла, горизонтального переполнения и необработанных JS-ошибок. Скриншоты: `output/playwright/dockhost-room-desktop.png`, `output/playwright/dockhost-room-mobile.png` (локальные). Это подтверждает публикацию интеграции сайта. Реальная генерация по-прежнему требует отдельного GPU-обработчика.
