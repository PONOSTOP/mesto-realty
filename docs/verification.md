# Проверка «Место»

Исторический отчёт первой версии. Проверки после перехода на коммерческую недвижимость — в [b2b-verification.md](b2b-verification.md).

Проверено 30 сентября 2026 года на Windows, Node.js 24.18.0, PostgreSQL 17 в Docker и Chromium (Playwright). Серверные и браузерные тесты выполняются с реальной PostgreSQL, без подмены базы localStorage или моками.

## Автоматические проверки

| Команда | Результат |
|---|---|
| `npm test` | 10 проверок валидации, безопасного HTML/URL и пустых фильтров |
| `npm run test:api` | 15 проверок API и production-конфигурации |
| `npm run test:browser` | 10 проверок в Chromium |
| `npm run format:check` | Форматирование проходит |
| `npm audit --omit=dev` | 0 известных уязвимостей на момент проверки |

В счётчики Node test runner включены группирующие тесты. Последние прогоны завершились без ошибок. Для повторения нужны отдельная БД `mesto_test`, `TEST_DATABASE_URL` и установленный Chromium; команды приведены в README.

Покрытие API: bcrypt, HttpOnly, CSRF и Origin, регистрация/выход/вход, приватный черновик, публикация только с фото, SQL-фильтры, инъекционные строки, скрытие приватных полей, контакты, уникальность избранного, состояние избранного в связанных карточках, запрет изменения и удаления чужих объявлений/фото, профиль и аватар, сохранность сессии при пересоздании Express, удаление с каскадами. Отдельно проверены production HTTPS, Secure-cookie, HSTS и rate limit авторизации.

Изображения: валидный PNG загружается и отдаётся как WebP; файл с SVG-содержимым и MIME JPEG отвергается; файл больше 8 МБ отвергается. Изображения черновиков недоступны анонимно. У опубликованного объявления нельзя удалить последнюю фотографию.

## Сквозной браузерный сценарий

1. Зарегистрирован новый пользователь, выполнены выход и повторный вход.
2. Заполнено объявление, выбран файл и показан предпросмотр двух фотографий, объект опубликован.
3. Открыты галерея и телефон. Строка `<img ... onerror=...>` в описании показана текстом, не как HTML.
4. Объект найден через каталог; параметры сохранены в URL. Избранное сохранилось после обновления страницы.
5. Изменены название, цена и фотографии; объект снят с публикации и опубликован снова.
6. Изменены имя, телефон, описание профиля и аватар; данные сохранились после обновления.
7. Объявление удалено из кабинета с подтверждением; зависимые записи и избранное удалены.

Проверены главная, каталог, объект, профиль и публикация на ширинах 390, 768 и 1440 px: горизонтального переполнения страницы нет (допуск измерения 1 px). В основном браузере отдельно проверены страницы каталога с 12 и 3 объектами, сортировка и загрузка фотографий. Консоль обычного сценария без ошибок. Скриншоты сохраняются в `output/playwright/`.

## Сетевые ошибки и исправления ревью

- После успешного INSERT тест намеренно обрывает ответ первоначального POST. Форма объясняет неопределённый результат и блокирует повторный POST; в кабинете ровно один черновик.
- При обрыве запроса выхода отображается сообщение и кнопка снова доступна; JS-исключений нет.
- Сердечки в других объявлениях автора получают настоящее состояние избранного текущего пользователя.
- Ошибки формы направляются в общий доступный блок, а не в блок фотографий.
- Пустой фильтр комнат остаётся «Не важно», несмотря на порядок числовых ключей опций JavaScript.
- Адрес перехода после входа проверяется после нормализации URL и не может отправить пользователя на другой origin.

Исходные замечания и повторное ревью: [review-report.md](review-report.md).

## Реальный перезапуск

Помимо автоматического пересоздания Express выполнены остановка процесса Node.js и `docker compose restart db`. После повторного запуска сохранены авторизация в том же браузере, изменённый профиль, тот же аватар и все 15 демонстрационных объектов. Повторное выполнение seed добавило 0 объектов.

## Границы проверки

Проверен локальный запуск и production-настройки через тестовый доверенный proxy. Публичное развёртывание, выдача TLS-сертификата и нагрузочный тест не выполнялись. HTTPS и reverse proxy нужно настроить на выбранном сервере по README. Rate limit рассчитан на один процесс; файлы и база требуют постоянного хранения и резервного копирования.
